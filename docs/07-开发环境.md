# LinkNest — 开发环境

> 本文只记录环境、构建、日志和工具故障。功能、技术概括和验证记录见 [02-需求文档.md](./02-需求文档.md)。

- 更新日期：2026-10-18
- 已使用的 Flutter 版本：3.47.2

## 1. 环境要求

### Android（Windows）

| 组件 | 当前配置 |
|---|---|
| Flutter | 3.47.2 |
| JDK | Temurin 21；Gradle 要求 17～25 |
| Android SDK | Platform 36、Build Tools 36.0.0 |
| NDK | 28.2.13676358 |
| Pub Cache | 与仓库同在 E 盘，当前为 `E:\FlutterPubCache` |
| 其他 | Android platform-tools、Node.js、可访问 Google Maven 的网络 |

关键环境变量：

```text
JAVA_HOME=C:\Users\<你的用户名>\.jdks\temurin-21.0.12.1
PUB_CACHE=E:\FlutterPubCache
PATH 包含 Flutter/bin、JAVA_HOME/bin 和 Android platform-tools
```

首次配置：

```bash
flutter config --jdk-dir="C:\Users\<你的用户名>\.jdks\temurin-21.0.12.1"
flutter doctor --android-licenses
flutter doctor -v
```

Android SDK 使用新版 CLI 时，组件名使用斜杠格式：

```bash
android sdk install "platforms/android-36"
android sdk install "build-tools/36.0.0"
android sdk install "ndk/28.2.13676358"
```

### iOS（macOS）

需要 Flutter 3.47.2、兼容当前 Flutter 和目标 iOS 的 Xcode、CocoaPods、Apple ID 与真机。首次配置：

```bash
xcode-select --install
brew install cocoapods
xcodebuild -downloadPlatform iOS
flutter doctor -v
```

在 Xcode 打开 `host_app/ios/Runner.xcworkspace`，为 Runner 选择 Team 并启用自动签名。iPhone 需开启开发者模式，并信任开发者证书。

Runner 的 Debug/Profile/Release 已引用 `Runner/Runner.entitlements`，但当前文件未启用 **Hotspot Configuration** 与 **Access Wi-Fi Information**。因此 iPhone 当前使用系统相机扫描 Wi-Fi 码；App 内原生自动入网代码和恢复开关保留，取得合适的付费签名能力后再启用并复测。

## 2. 日常命令

在 `host_app/` 运行：

```bash
flutter pub get
flutter analyze
flutter test
flutter devices
flutter run -d <设备ID>
flutter build apk --debug
flutter build ios --debug --no-codesign
```

Android App 模块 lint：

```bash
cd android
./gradlew :app:lintDebug -x :mobile_scanner:lintDebug
```

`flutter run` 中按 `r` 热重载，按 `R` 热重启，按 `q` 退出。修改 Kotlin、Swift 或内置 Web 资产后需要重新运行 App，热重载不生效。

## 3. Web 构建与同步

Host 从 `host_app/assets/web/` 提供页面，不直接读取 `web/src/`。修改 Web 后在 `web/` 运行：

```bash
npm install
npm test
npm run build:host
```

`build:host` 会构建并原子更新 Host 资产。`host_app/assets/web/` 已纳入 Git，必须和 Web 源码一起提交。

## 5. 已知环境问题

| 现象 | 原因与处理 |
|---|---|
| `flutter` 找不到 | 把 Flutter `bin` 加入 PATH，或使用完整路径 |
| Gradle 使用 Java 11 | 设置 `JAVA_HOME` 和 `flutter config --jdk-dir` 为 JDK 17～25 |
| Android license 未接受 | 运行 `flutter doctor --android-licenses` |
| SDK/NDK 缺失 | 按第 1 节安装 Platform 36、Build Tools 36 和 NDK 28.2 |
| Maven 下载超时 | 配置能覆盖 Gradle/Java 的网络代理 |
| 多个 `adb` | PATH 只保留 Android SDK 的 platform-tools |
| Windows lint 报跨盘路径 | 让 `PUB_CACHE` 与仓库位于同一盘，再运行 `flutter pub get` |
| Web 修改后 App 仍显示旧页面 | 运行 `npm run build:host` 并重新启动 App |
| MIUI 拒绝安装 | 开启“USB 安装”和“USB 调试（安全设置）”，并接受手机弹窗 |
| iOS 找不到可用目标 | 下载 iOS Platform，检查开发者模式、签名和设备信任 |
| 构建提示 `nsd_android` 仍应用 Kotlin Gradle Plugin | `nsd 5.0.1` 的上游兼容性预警，当前 Debug APK 可正常构建；升级 Flutter 或 `nsd` 后复查 |

### `mobile_scanner 7.4.2` lint 例外

根工程 `lintDebug` 会被该插件源码中的 4 个 lint error 阻断，涉及 CameraX 实验 API opt-in 和 `VisibleForTesting` 注解。它不属于 LinkNest 业务代码，也不影响当前 debug APK 构建。

目前不修改 Pub Cache、不维护私有 Fork，也不为此降级工具链。使用以下命令检查 LinkNest App 模块，并如实记录插件被排除：

```bash
./gradlew :app:lintDebug -x :mobile_scanner:lintDebug
```

升级 Flutter、Android Gradle Plugin、CameraX 或 `mobile_scanner` 后重新运行根工程 lint；上游修复并完成扫码回归后取消该例外。

### Android 生成文件

Flutter 会重写未纳入 Git 的 `android/local.properties`。Windows 盘符路径可能触发 lint 的 `PropertyEscape`，项目只关闭这一项；不要手工维护该文件。

## 6. Android Release 构建与安装

以下命令使用 PowerShell。已有密钥和配置时，直接从“构建”开始；不要每次生成新密钥。

### 首次配置签名

在仓库根目录执行，仅在对应文件不存在时操作：

```powershell
keytool -genkeypair -v -keystore host_app/android/linknest-release.jks -storetype JKS -keyalg RSA -keysize 3072 -validity 10000 -alias release
Copy-Item host_app/android/key.properties.example host_app/android/key.properties
```

按提示设置密钥库密码、证书信息和密钥密码；`keytool` 找不到时，使用 `$env:JAVA_HOME/bin/keytool.exe`。编辑本地 `host_app/android/key.properties`：

```properties
storePassword=创建时设置的密钥库密码
keyPassword=创建时设置的密钥密码
keyAlias=release
storeFile=../linknest-release.jks
```

- 两个密码可以相同，但必须与实际密钥一致；只修改配置里的密码不会创建密钥或修改密钥密码。
- `storeFile` 相对于 `host_app/android/app/`，上述路径指向 `host_app/android/linknest-release.jks`。也可写绝对路径，如 `E:/LinkNestKeys/linknest-release.jks`，Windows 建议使用 `/`。
- `keyAlias` 必须对应密钥库内实际别名。已有密钥使用其原路径、别名和密码。
- 密钥和密码需妥善备份。`key.properties`、`*.jks` 和 `*.keystore` 已被 Git 忽略，不得提交。

### 构建

在仓库根目录进入 `host_app/`，执行：

```powershell
cd host_app
flutter pub get
flutter build apk --release
```

产物：`host_app/build/app/outputs/flutter-apk/app-release.apk`（相对于仓库根目录）。首个稳定版 `1.3.0+3` 的验签副本命名为同目录下的 `LinkNest_1.3.apk`；后续版本按实际版本号命名。版本来自 `pubspec.yaml` 的 `version`；对外更新时递增 `+` 后的构建号，规则见 [06-版本管理.md](./06-版本管理.md)。本地构建 Release 不等于正式发布。

### 安装

手机开启 USB 调试、连接电脑并允许调试授权。在 `host_app/` 执行：

```powershell
adb devices
adb install -r build/app/outputs/flutter-apk/LinkNest_1.3.apk
```

多设备时用 `adb -s <设备序列号> install -r build/app/outputs/flutter-apk/LinkNest_1.3.apk`。后续版本改用对应文件名；也可将 APK 复制到手机，点击安装，并允许对应文件管理器安装未知应用。

同包名、同签名且版本符合要求时，`-r` 覆盖安装并保留数据。Debug 与当前 Release 使用不同签名，无法直接覆盖；`INSTALL_FAILED_UPDATE_INCOMPATIBLE` 通常表示签名冲突。若决定卸载旧包再装，先把需要的照片和视频保存到系统相册：卸载会清除 App 内空间、文件与历史记录，保存媒体不会保留空间索引。不要为普通升级主动卸载。

### 后续替换 JKS

JKS 是密钥的容器；能否覆盖升级取决于里面的签名密钥和证书，不取决于文件名或密码。

| 情况 | 处理方式与影响 |
|---|---|
| 移动、重命名或恢复同一 JKS 备份 | 修改 `storeFile`；签名不变，可正常覆盖升级 |
| 将原私钥及证书迁入另一个密钥库，或修改密码/别名 | 修改相应配置并核对证书；保留原签名身份时仍可覆盖升级，仅改配置不会修改密钥库 |
| 重新生成全新密钥，即使文件名、别名和密码相同 | 当前构建未配置签名轮换，不能直接覆盖旧包；测试阶段可保存媒体后卸载重装，已分发版本不要直接换新密钥 |
| 丢失原密钥且无备份 | 当前直接分发 APK 的方式无法再用原签名更新；新密钥不能恢复原签名 |
| 以后接入 Google Play App Signing | 上传密钥可按 Play 流程重置，不等于更换用户安装包的应用签名密钥；当前直接分发的 APK 使用本地 Release 密钥承担应用签名 |

替换前保留旧文件；在仓库根目录对旧、新密钥分别执行下列命令（替换路径和别名，密码交互输入），比较证书 SHA-256 指纹：

```powershell
keytool -list -v -keystore host_app/android/linknest-release.jks -alias release
```

相同指纹可确认签名证书一致；仍需确保密钥库包含对应私钥。确需更换签名身份且要保留覆盖升级能力时，应单独设计并验证签名轮换，需原密钥及兼容性处理，不能仅替换 JKS。参考 [Android 签名规则](https://developer.android.com/studio/publish/app-signing)与 [apksigner 签名轮换](https://developer.android.com/tools/apksigner)。构建命令参考 [Flutter Android 发布说明](https://docs.flutter.dev/deployment/android)。
