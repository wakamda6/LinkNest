# LinkNest 宣传网站部署清单

> 交给负责实际部署的 agent 使用。本文只约定宣传网站的构建、发布和验收，不涉及 LinkNest App 功能、Android 签名或 iOS 上架。

- 开源仓库：`https://github.com/wakamda6/LinkNest`
- 正式地址：`https://wakamda.fun/linknest/`
- 部署形态：纯静态单页网站，无后端、数据库、账号或多语言切换
- 网站源码目录：`website/`（待创建）
- 预期构建产物：`website/dist/`
- 下载来源：GitHub Releases，APK 不放进网站目录或 Git 源码历史
- 服务器：复用已有 `wakamda.fun` 主站、HTTPS 和服务器，不改变主站根路径内容

## 1. 开始前确认

- [ ] 仓库已完成公开前检查并公开，GitHub 链接可以匿名访问。
- [ ] `website/` 已创建，实际构建脚本以 `website/package.json` 为准。
- [ ] Vite 的基础路径为 `/linknest/`，页面和资源不依赖域名根路径。
- [ ] 网站只使用中文，不包含语言切换、iOS 下载或占位按钮。
- [ ] Android Release、标签、APK 文件名和更新说明已发布。
- [ ] 网站中的 APK 地址与实际 Release 资产完全一致，不凭空推测下载地址。
- [ ] 已确认 APK 的版本、大小和 SHA-256，页面展示值与 Release 一致。
- [ ] 已了解服务器系统、Web 服务类型、主站配置位置和实际 Web 根目录。
- [ ] 已取得部署权限；凭据通过安全渠道提供，不写入仓库、命令日志或本文档。

## 3. 本地构建检查

在仓库根目录执行：

```bash
cd website
npm ci
```

如果 `package.json` 提供测试脚本，再运行 `npm test`，随后运行实际生产构建脚本，预期为：

```bash
npm run build
```

构建后检查：

- [ ] 生成完整的 `website/dist/`，入口为 `dist/index.html`。
- [ ] HTML 中静态资源以 `/linknest/` 开头，或使用能在该路径下正确解析的相对地址。
- [ ] 不存在指向 `/assets/`、`/` 根首页或开发服务器地址的错误引用。
- [ ] 页面不依赖 `localhost`、内网 API、Node.js 进程或运行时环境变量。
- [ ] 图片、图标、字体和分享封面均已包含在构建产物中。
- [ ] 无真实用户照片、软著资料、签名文件、`.env`、日志或源代码调试数据进入产物。
- [ ] 本地预览时直接访问 `/linknest/`，刷新、锚点跳转和 Android 下载均正常。

## 4. 服务器部署原则

- [ ] 只部署 `dist/` 内容，不部署 `node_modules/`、`.git/`、源码目录或本地配置。
- [ ] 只修改 LinkNest 的独立目标目录，绝不对主站 Web 根目录整体执行清空或 `rsync --delete`。
- [ ] 若目标目录已有版本，先备份；若不存在，先确认它不是主站已有内容。
- [ ] 先上传至同文件系统的临时目录，检查文件清单和权限后再切换。
- [ ] 保留 `index.html`、带内容哈希的静态资源及网站实际引用的其他文件。
- [ ] 文件应可由 Web 服务用户读取，目录不得向 Web 服务开放不必要写权限。
- [ ] 部署过程不更改主站其他路径，不覆盖现有 TLS、防火墙或全局安全设置。

## 5. Web 服务配置

优先沿用主站现有 `root`、MIME、日志和 HTTPS 配置。Nginx 环境下，逻辑应等价于：

```nginx
location = /linknest {
    return 308 /linknest/;
}

location /linknest/ {
    try_files $uri $uri/ =404;
}
```

以上仅表达路由要求，部署 agent 必须根据现有配置合并，不得直接覆盖主站配置。文件应位于主站 Web 根目录下的 `linknest/`。如果使用其他 Web 服务或 `alias`，按其语义单独验证，不能机械复制 Nginx 示例。

缓存建议：

- [ ] `index.html` 使用协商缓存或 `no-cache`，确保发布后可及时取得新入口。
- [ ] 带内容哈希的 JS、CSS 和静态资源可使用长期缓存及 `immutable`。
- [ ] 图片若没有内容哈希，不使用不可撤销的长期缓存。
- [ ] 单页第一版无前端路由；未知静态文件返回 404，不把所有路径都回退到首页。

配置修改后先执行对应服务的配置检查，例如 Nginx 的 `nginx -t`；通过后再 reload，不使用强制重启代替配置检查。

## 6. Android 下载检查

- [ ] 下载按钮指向 GitHub Releases 中实际存在、与页面版本一致的 APK。
- [ ] “查看历史版本”指向 `https://github.com/wakamda6/LinkNest/releases`。
- [ ] “查看源代码”指向 `https://github.com/wakamda6/LinkNest`。
- [ ] 使用匿名环境验证下载，避免把维护者登录状态误认为公开可用。
- [ ] 跟随 GitHub 重定向后能够下载完整文件，不将 HTML 登录页或错误页保存为 APK。
- [ ] 核对下载文件大小与 SHA-256；GitHub 返回 `application/octet-stream` 时可以接受。
- [ ] 第一版不由主站代理或中转 APK，不额外暴露服务器下载带宽。
- [ ] 安装说明提示允许浏览器或文件管理器安装未知应用，并保留同签名覆盖升级说明。

可使用下列方式检查响应，但文件名和 URL 必须替换为实际 Release 值：

```bash
curl -I -L "<实际 APK 下载地址>"
```

完整下载与摘要检查应在临时目录进行，检查文件不得留在网站公开目录。

## 7. 上线验收

### 页面与资源

- [ ] `https://wakamda.fun/linknest/` 返回成功，页面完整显示。
- [ ] `https://wakamda.fun/linknest` 能跳转到带末尾斜杠的地址。
- [ ] HTML、JS、CSS、图标和图片全部通过 HTTPS 加载，无混合内容或 404。
- [ ] 浏览器控制台无资源路径、JavaScript 或跨域错误。
- [ ] 首屏、功能、使用方法、FAQ、开源链接和页脚均显示最终中文文案。
- [ ] 手机窄屏和桌面宽屏无横向溢出，按钮可点击，文字与对比度可读。
- [ ] 页面内锚点跳转正常；不存在的文件按预期返回 404。

### 主站回归

- [ ] `https://wakamda.fun/` 及原有主要路径保持正常。
- [ ] 主站原有证书、跳转、缓存和其他服务未受影响。
- [ ] 服务器错误日志中没有本次部署引入的持续 404、权限或配置错误。

### 下载与开源

- [ ] 手机网络环境下点击 Android 下载可取得 APK。
- [ ] APK 文件名、版本、大小和 SHA-256 与 Release 及页面一致。
- [ ] GitHub 源码、Issues 和历史版本链接均可匿名访问。
- [ ] 网站没有 iOS 下载入口、虚假统计数据或尚未实现的能力宣传。

## 8. 回滚

- [ ] 保留上一份可用的 `linknest/` 目录和变更前的 Web 服务配置。
- [ ] 出现异常时只回滚 LinkNest 子目录及本次新增配置，不重置整台服务器。
- [ ] 回滚后重新检查 `/linknest/` 和主站根路径。
- [ ] 若仅 APK 链接错误，优先修正页面并重新部署，不删除正式 Release 或更换签名包。
